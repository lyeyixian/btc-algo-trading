# Data Model: BTC Multi-Strategy Trading Platform

**Feature**: 002-btc-trading-platform  
**Date**: 2025-01-27  
**Purpose**: Define domain entities, relationships, validation rules, and state transitions

## Core Entities

### Strategy

Represents a trading strategy definition with configuration, logic, and risk settings.

**Attributes**:
- `id` (UUID, primary key)
- `name` (string, required, unique)
- `type` (enum: TREND_FOLLOWING, MEAN_REVERSION, GRID_TRADING, ORDER_CHASING)
- `config` (JSON, strategy-specific parameters)
- `risk_limits` (JSON, position limits, drawdown thresholds)
- `status` (enum: INACTIVE, ACTIVE, PAUSED, STOPPED)
- `created_at` (timestamp)
- `updated_at` (timestamp)

**Validation Rules**:
- Name must be unique
- Config must match strategy type schema
- Risk limits must include: max_position_size, max_drawdown_threshold, warning_drawdown_threshold
- Status transitions: INACTIVE → ACTIVE → PAUSED/STOPPED → INACTIVE

**Relationships**:
- One-to-many: Orders
- One-to-many: Positions
- One-to-many: Backtest Results
- Many-to-one: Trading Sessions (many strategies per session)

**State Transitions**:
```
INACTIVE → ACTIVE (start strategy)
ACTIVE → PAUSED (pause for review)
ACTIVE → STOPPED (error or shutdown)
PAUSED → ACTIVE (resume)
PAUSED → STOPPED (force stop)
STOPPED → INACTIVE (cleanup)
```

### Order

Represents a trading order (buy/sell) generated by a strategy.

**Attributes**:
- `id` (UUID, primary key)
- `client_order_id` (string, required, unique, for idempotency)
- `strategy_id` (UUID, foreign key to Strategy)
- `session_id` (UUID, foreign key to TradingSession)
- `side` (enum: BUY, SELL)
- `type` (enum: MARKET, LIMIT)
- `quantity` (decimal, required, > 0)
- `price` (decimal, nullable for MARKET orders)
- `status` (enum: PENDING, SUBMITTED, FILLED, PARTIALLY_FILLED, CANCELLED, REJECTED)
- `filled_quantity` (decimal, default 0)
- `average_fill_price` (decimal, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)
- `filled_at` (timestamp, nullable)

**Validation Rules**:
- client_order_id must be unique (prevents duplicate orders)
- quantity must be positive
- price required for LIMIT orders, nullable for MARKET orders
- filled_quantity <= quantity
- Status transitions enforced

**Relationships**:
- Many-to-one: Strategy
- Many-to-one: TradingSession
- One-to-many: OrderFills (for partial fills)

**State Transitions**:
```
PENDING → SUBMITTED (order sent to exchange/simulator)
SUBMITTED → FILLED (complete execution)
SUBMITTED → PARTIALLY_FILLED (partial execution)
SUBMITTED → CANCELLED (cancelled before fill)
SUBMITTED → REJECTED (exchange/simulator rejection)
PARTIALLY_FILLED → FILLED (remaining quantity filled)
```

### Position

Represents current market exposure for a strategy.

**Attributes**:
- `id` (UUID, primary key)
- `strategy_id` (UUID, foreign key to Strategy, unique per strategy)
- `session_id` (UUID, foreign key to TradingSession)
- `asset` (string, default "BTC")
- `quantity` (decimal, can be negative for short positions)
- `average_entry_price` (decimal)
- `unrealized_pnl` (decimal, calculated)
- `realized_pnl` (decimal, accumulated)
- `updated_at` (timestamp)

**Validation Rules**:
- One position per strategy per session (unique constraint on strategy_id + session_id)
- Quantity can be negative (short positions)
- Average entry price must be positive if quantity != 0

**Relationships**:
- Many-to-one: Strategy
- Many-to-one: TradingSession

**Calculated Fields**:
- `unrealized_pnl = (current_price - average_entry_price) * quantity`
- Updated on each order fill or market price update

### MarketData

Represents real-time or historical price and volume data for BTC.

**Attributes**:
- `id` (UUID, primary key, for database storage only)
- `timestamp` (timestamp, indexed, for TimescaleDB hypertable)
- `exchange` (string, exchange name)
- `symbol` (string, e.g., "BTC/USDT")
- `open` (decimal)
- `high` (decimal)
- `low` (decimal)
- `close` (decimal)
- `volume` (decimal)
- `source` (enum: LIVE, HISTORICAL)

**Validation Rules**:
- All OHLCV values must be positive
- high >= max(open, close)
- low <= min(open, close)
- Timestamp must be within reasonable bounds (no future data)

**Relationships**:
- Referenced by: Strategies (for signal generation)
- Stored in TimescaleDB hypertable for efficient time-series queries

**Storage**:
- Real-time: In-memory cache + database (hypertable)
- Historical: Parquet files + database (for querying)

### TradingSession

Represents an active paper trading or live trading period.

**Attributes**:
- `id` (UUID, primary key)
- `mode` (enum: PAPER, LIVE)
- `status` (enum: RUNNING, PAUSED, STOPPED, COMPLETED)
- `initial_balance` (decimal, starting balance)
- `current_balance` (decimal, updated)
- `start_time` (timestamp)
- `end_time` (timestamp, nullable)
- `created_at` (timestamp)
- `updated_at` (timestamp)

**Validation Rules**:
- initial_balance must be positive
- current_balance >= 0 (prevent negative balances)
- end_time must be >= start_time
- Status transitions enforced

**Relationships**:
- One-to-many: Strategies (active in session)
- One-to-many: Orders
- One-to-many: Positions
- One-to-one: PerformanceReport

**State Transitions**:
```
[New] → RUNNING (session started)
RUNNING → PAUSED (manual pause or auto-shutdown)
PAUSED → RUNNING (resume)
RUNNING → STOPPED (error or shutdown)
PAUSED → STOPPED (force stop)
STOPPED → COMPLETED (session ended, report generated)
```

### RiskMetrics

Represents portfolio and strategy-level risk measurements.

**Attributes**:
- `id` (UUID, primary key)
- `timestamp` (timestamp, indexed, for TimescaleDB hypertable)
- `strategy_id` (UUID, foreign key to Strategy, nullable for portfolio-level)
- `session_id` (UUID, foreign key to TradingSession)
- `current_drawdown` (decimal, percentage)
- `max_drawdown` (decimal, percentage)
- `exposure` (decimal, total position value)
- `leverage` (decimal, calculated)
- `metric_type` (enum: STRATEGY, PORTFOLIO)

**Validation Rules**:
- Drawdown values between 0 and 100 (percentages)
- Exposure >= 0
- Leverage >= 0
- Either strategy_id (STRATEGY) or NULL (PORTFOLIO) for metric_type

**Relationships**:
- Many-to-one: Strategy (optional)
- Many-to-one: TradingSession

**Storage**:
- TimescaleDB hypertable for efficient time-series queries
- Sampled periodically (e.g., every minute) or on significant changes

### BacktestResult

Represents results from a historical strategy test.

**Attributes**:
- `id` (UUID, primary key)
- `strategy_id` (UUID, foreign key to Strategy)
- `strategy_config_snapshot` (JSON, strategy config at time of backtest)
- `start_date` (date)
- `end_date` (date)
- `total_return` (decimal, percentage)
- `sharpe_ratio` (decimal)
- `max_drawdown` (decimal, percentage)
- `win_rate` (decimal, percentage)
- `profit_factor` (decimal)
- `number_of_trades` (integer)
- `total_transaction_costs` (decimal)
- `created_at` (timestamp)

**Validation Rules**:
- end_date >= start_date
- win_rate between 0 and 100
- max_drawdown between 0 and 100
- number_of_trades >= 0
- strategy_config_snapshot must match strategy type schema

**Relationships**:
- Many-to-one: Strategy

---

### PerformanceReport

Represents aggregated performance statistics for a trading session or backtest.

**Attributes**:
- `id` (UUID, primary key)
- `session_id` (UUID, foreign key to TradingSession, nullable if backtest)
- `backtest_result_id` (UUID, foreign key to BacktestResult, nullable if session)
- `report_type` (enum: SESSION, BACKTEST)
- `start_time` (timestamp)
- `end_time` (timestamp)
- `total_return` (decimal, percentage)
- `sharpe_ratio` (decimal)
- `max_drawdown` (decimal, percentage)
- `win_rate` (decimal, percentage)
- `number_of_trades` (integer)
- `strategy_breakdown` (JSON, per-strategy metrics)
- `created_at` (timestamp)

**Validation Rules**:
- Either session_id or backtest_result_id must be set (not both)
- report_type matches which ID is set
- end_time >= start_time
- All metrics within valid ranges

**Relationships**:
- One-to-one: TradingSession (optional)
- One-to-one: BacktestResult (optional)

---

### OrderFill

Represents a partial or complete order fill (for tracking partial fills).

**Attributes**:
- `id` (UUID, primary key)
- `order_id` (UUID, foreign key to Order)
- `quantity` (decimal, filled quantity)
- `price` (decimal, fill price)
- `filled_at` (timestamp)
- `commission` (decimal, trading fee)

**Validation Rules**:
- quantity > 0
- price > 0
- Sum of fills for an order <= order quantity

**Relationships**:
- Many-to-one: Order

## Entity Relationships Summary

```
TradingSession (1) ──< (many) Strategy
Strategy (1) ──< (many) Order
Strategy (1) ──< (1) Position (per session)
Order (1) ──< (many) OrderFill
TradingSession (1) ──< (1) PerformanceReport
Strategy (1) ──< (many) BacktestResult
Strategy (1) ──< (many) RiskMetrics (optional)
TradingSession (1) ──< (many) RiskMetrics
```

## Database Design Notes

- **PostgreSQL + TimescaleDB**:
  - Regular tables: Strategy, Order, Position, TradingSession, BacktestResult, PerformanceReport, OrderFill
  - TimescaleDB hypertables: MarketData, RiskMetrics (for efficient time-series queries)
  
- **Indexes**:
  - Strategy: name (unique), type, status
  - Order: client_order_id (unique), strategy_id, session_id, status, created_at
  - Position: strategy_id + session_id (unique), session_id
  - MarketData: timestamp (primary time index), exchange + symbol + timestamp
  - RiskMetrics: timestamp (primary time index), strategy_id + timestamp, session_id + timestamp

- **Constraints**:
  - Foreign key constraints on all relationships
  - Unique constraints on: strategy name, client_order_id, strategy+session for positions
  - Check constraints on: quantity > 0, percentages in valid ranges, dates logical
